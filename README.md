# 知华采购支出分析

**采购支出登记 → 自动分类与异常识别 → 人工复核 → 入账留痕。** 这是上海如静知华信息科技有限公司的企业支出分析公开源码版，面向采购、财务和内审协同；项目主页：[知华科技官网](https://www.zhuatech.cn/)。

## 一个可复现的业务例子

供应商常规单笔金额设为 100 元。第一张 50 元的“软件许可”票据被分类为 SOFTWARE 且通过规则检查；第二张使用相同供应商和票据号、金额 250 元时，同时命中“重复票据”和“超过基线两倍”，风险分数为 100，进入独立复核，不能直接入账。这个过程有自动化 HTTP 验收测试，不是静态演示数据。

当前主要模块：

- 供应商：信用代码去重、金额基线、启用档案；
- 采购支出：日期、金额、票据号、供应商关联及分类结果；
- 分析流水：保存分类、风险分数、触发原因及规则版本；
- 审核与入账：高风险支出经非提交人批准或驳回；通过后再确认入账；
- 管理端：账号、角色、审计、附件、CSV 导出、幂等和租户隔离。

## “AI”具体在哪里

`cn.zhuatech.spendai.InsightProvider` 定义了分类与风险分析接口。默认实现用**本地可解释规则**处理文字类别、重复票据和金额异常，能在没有模型账号时完整运行；目前**不会调用外部大模型**。后续可替换为国内模型实现，但建议仍把金额、重复号和审批门禁保留为服务端确定性校验，不能让模型输出直接入账。

H5 业务界面显示供应商、支出与分析流水；`/admin` 提供权限与操作审计。前后端分离，后端为 Java 21 / Spring Boot 4，持久化使用 MySQL 8.4，前端为 Vue 3 / Vite。

## 启动与验收

1. 复制 `.env.example` 到 `.env`，配置 MySQL 和四种角色的独立强密码。
2. 运行 `docker compose up -d --build`。
3. 运行 `sh scripts/test.sh`；脚本执行后端 H2/MySQL 兼容测试、前端单测与生产构建。CI 配置 MySQL 复测。

默认访问 `http://127.0.0.1:8088`，后端健康检查 `http://127.0.0.1:18080/api/health`。完整接口字段与状态由登录后的 `GET /api/catalog` 提供；写操作使用幂等键。演示密码不能用于生产。
